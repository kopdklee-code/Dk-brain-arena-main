# 단 하나의 숫자 (`unique-number`)

1~20 중 숫자 하나를 고르는 실시간 숫자 심리전입니다. 최대 29명이 스마트폰으로 참여하고, 3라운드로 진행합니다.
개발 기준: 「단 하나의 숫자」 개발 마스터 지시문 v1.1 (규칙 변경 금지).

## 규칙 (v1.1 §1.2)
1. 같은 숫자를 2명 이상 고르면 그 숫자는 무효입니다.
2. 정확히 한 명만 고른 숫자는 유효합니다.
3. 유효 숫자 중 가장 작은 숫자를 고른 참가자가 그 라운드에서 1승합니다.
4. 유효 숫자가 없으면 그 라운드는 승자가 없습니다.
5. 3라운드 누적 승리 횟수로 순위를 정하고, 같으면 공동 순위입니다.
6. 탈락은 없습니다. 보너스, 빠른 제출 보상, 가중치, 동점 해소 기준은 없습니다.

- 라운드당 선택 시간은 기본 40초입니다. 마감은 서버 시각 기준입니다.
- 마감 전에는 숫자를 바꿔 다시 제출할 수 있고, 서버가 마지막으로 확정한 숫자만 인정합니다.
- 제출하지 않으면 그 라운드는 미참여로 기록되며 집계하지 않습니다.

| `rules.js` | 판정 엔진(`judge`, `standings`)과 진행 상태(순수 함수). 숫자 제출은 `playerInput` 계약으로 처리 |

## 진행 단계 (게임 내부 상태)
플랫폼 방 상태(대기실 → 진행 중 → 종료)와는 따로 관리합니다.

| 단계 | 의미 | 다음 |
|---|---|---|
| `LOBBY` | 게임 시작 후 라운드 시작 전 (규칙 설명, 재진행 대기) | 진행자 `start-round` → `ROUND_ACTIVE` |
| `ROUND_ACTIVE` | 숫자 선택·제출 (일시정지 가능) | 서버 시각으로 마감 시각이 지나면 `close-round` → `ROUND_CLOSED` |
| `ROUND_CLOSED` | 마감과 판정 확정, 공개 전. 판정은 서버 전용 상태에만 있음 | `reveal` → `ROUND_RESULT`, 또는 `void-round` → `LOBBY`(같은 라운드 다음 시도) |
| `ROUND_RESULT` | 결과 공개 (순차 연출 8초, 건너뛰기 가능) | 다음 라운드 `start-round`, 3라운드 뒤에는 `finish-game` |
| `GAME_FINISHED` | 종료 (정상 종료, 또는 `end-game` 비상 중단) | — |

## 행동 표
| 행동 | 누가 | 조건 |
|---|---|---|
| `submit {round, attempt, value}` | 참가자 | `ROUND_ACTIVE`, 일시정지 아님, **서버 시각 < 마감 시각**, 1~20 정수, 한 시도에 30번까지 변경 |
| `start-round {round[, attempt]}` | 진행자 | `LOBBY`(같은 라운드·시도) 또는 `ROUND_RESULT`(다음 라운드) |
| `pause` / `resume` | 진행자 | `ROUND_ACTIVE`. 일시정지하면 남은 시간을 보존하고, 재개하면 그 시간부터 이어감 |
| `close-round` | 진행자 화면(자동), 참가자 화면(예비) | 서버 시각 ≥ 마감 시각, 일시정지 아님. 여러 번 와도 한 번만 반영 |
| `reveal` | 진행자 | `ROUND_CLOSED`. 한 번만 반영 |
| `skip-reveal` | 진행자 | `ROUND_RESULT`. 공개 화면 연출을 바로 끝냄 |
| `void-round` | 진행자 | `ROUND_CLOSED`일 때만. 이번 시도를 점수에서 빼고 감사 기록에 남김 |
| `finish-game` | 진행자 | 3라운드 결과 공개 후 |
| `end-game` | 진행자 | 비상 중단. 공개된 결과만 남기고 공개 전 판정은 버림 |

## 데이터와 비공개 정보 (v1.1 §7.2 개념과 저장 위치)
| 개념 | 저장 위치 | 읽을 수 있는 사람 |
|---|---|---|
| GameRoom | `rooms/{roomId}` (코드·상태·`publicView`·`inputCounts`) | 로그인한 사용자 |
| Participant | `rooms/{roomId}/players/{uid}` (자리 번호·닉네임) | 로그인한 사용자 |
| Round·RoundResult(공개 전)·감사 기록 | `rooms/{roomId}/server/state.gameState` | 서버만 |
| Submission | `rooms/{roomId}/server/state/inputs/{playerId}` (라운드·시도·숫자·수정 횟수·서버 시각) | 서버만 |
| 본인 제출·지난 선택 | `rooms/{roomId}/private/{uid}` | 본인만 |
| RoundResult(공개 후)·GameResult | `publicView.results`·`standings`, 종료 시 `rooms/{roomId}.result` | 로그인한 사용자. 개인별 선택 목록은 공개하지 않음 |

- 진행 중과 공개 전에는 공개 문서, 진행자 문서, 다른 참가자 문서 어디에도 숫자나 분포가 없습니다. 진행자 화면도 제출 인원만 봅니다.
- 승리 횟수는 더해 나가지 않고, 공개된 결과 목록에서 매번 다시 집계합니다. 그래서 두 번 채점될 수 없습니다.

## 운영 안내 (강사용)
1. 진행자 화면 → 방 만들기 → **시작 전 점검**을 확인합니다.
   - 서버 응답, QR, 인원을 봅니다.
   - 로컬 주소(`127.0.0.1`)로 열었다면 휴대폰에서는 접속할 수 없습니다.
   - 네트워크 속도는 측정하지 않습니다.
2. "공개 화면 열기"로 프로젝터 화면을 엽니다. 참가자는 QR을 찍고 닉네임만 입력합니다.
3. 게임 시작(규칙 설명) → 1라운드 시작 → 40초 뒤 자동 마감 → 결과 공개 → 다음 라운드 → 최종 결과 발표.
4. 비상 상황
   - 네트워크 문제: 긴급 일시정지 → 재개
   - 마감 후 오류를 발견함: 라운드 무효화 → 같은 라운드 다시 시작
   - 공개된 결과에 문제가 있음: 게임 중단. 공개된 결과는 덮어쓰지 않습니다.
5. 새로고침해도 진행자, 참가자, 공개 화면 모두 현재 상태로 돌아옵니다. 참가자 수는 늘어나지 않습니다.

## 데이터 보존
기존 프로젝트에 보존·삭제 정책이 없고, 자동 삭제도 구현하지 않았습니다. 종료된 방의 데이터는 `rooms/{roomId}`와 그 하위 문서에 남습니다.
- 수집 정보: 닉네임과 익명 인증 ID뿐입니다.
- 정리 방법: 관리자가 Firebase 콘솔에서 종료된 방을 삭제하거나, 정책을 정한 뒤 TTL(만료 시각 필드)을 도입할 수 있습니다.
- 다른 게임이나 기존 데이터는 정리 대상이 아닙니다.
- 보존 기간은 **결정이 필요한 사항**입니다.
